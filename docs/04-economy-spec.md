# เศรษฐกิจ บัญชี และรายได้

> **สถานะ: ยังไม่ล็อก** ตัวเลขในเอกสารนี้เป็นกรอบสำหรับตัดสินใจ ไม่ใช่ค่าที่ตกลงแล้ว
> ตามแผน แพ็กและโฆษณาจะถูกกำหนด **หลังได้ตัวเลขการฟาร์มพื้นฐานจากระยะ C** เพื่อให้ตอบได้ว่า
> จ่ายหรือดูโฆษณาแล้วประหยัดเวลาเท่าไร และสายฟรีใช้เวลาเท่าไรจึงสร้างทีมที่แข่งขันได้

## บัญชีและการเชื่อมต่อ

เกมหลักเป็น **online-first** เพราะตัวละครและทรัพยากรมีคุณค่าแข่งขัน แต่ต้อง:

- พักแอปแล้วกลับมาต่อได้
- ดูคอลเลกชันที่เคยโหลดไว้ได้แม้ออฟไลน์
- มีสนามทดลองที่คำนวณบนเครื่องได้ (ใช้ `DarkMyst.Combat` ตัวเดียวกัน ไม่จ่ายรางวัล)

บัญชีเริ่มเป็น **guest** ได้ทันที แล้วเชื่อมกับบัญชีถาวรเพื่อกู้คืนและใช้ข้ามระบบ

**กรณีที่ต้องมีขั้นตอนชัดเจนตั้งแต่ต้น:** ผู้เล่นมีเซฟ guest บนเครื่องใหม่ แล้วเชื่อมกับ
บัญชีถาวรที่มีเซฟเดิมอยู่แล้ว — ต้องแสดงเซฟทั้งสองฝั่งพร้อมข้อมูลพอให้เลือกได้
(เลเวลสูงสุด จำนวนตัวละคร เวลาเล่นล่าสุด) และเก็บเซฟที่ถูกทิ้งไว้ระยะหนึ่งเผื่อเลือกผิด

## สกุลเงินและทรัพยากร

| ทรัพยากร | ได้จาก | ใช้ทำอะไร | ซื้อได้ |
| --- | --- | --- | --- |
| ทอง | การต่อสู้ ภารกิจ | evolve, อัปเลเวลสกิล | ทางอ้อม |
| ตรา / แก่น | ด่านเฉพาะ เหตุการณ์ | วัตถุดิบ evolve | จำกัด |
| พลังสำรวจ | ฟื้นตามเวลา | เริ่มการสำรวจ | ใช่ |
| อัญมณี (พรีเมียม) | เติมเงิน ภารกิจ ของแจก | พลังสำรวจ, ช่องเก็บ, Reforge Stone, **สิทธิ์สุ่มตัวละคร** | ใช่ |

**อัญมณีซื้อ *โอกาส* และ *เวลา* — ไม่เคยซื้อความได้เปรียบที่การันตี** และไม่เคยซื้อข้าม
บันได evolve เพราะจุดขายของเกมคืองานปั้นที่มีคุณค่า — ถ้าซื้อข้ามได้ คุณค่านั้นหายไปทันที

> **แก้กฎข้อนี้เมื่อ 2026-09-23 ตามการตัดสินใจของเจ้าของโปรเจกต์:** เดิมเขียนว่า
> *"อัญมณีซื้อเวลาและความสะดวก ไม่ใช่สแตท"* ซึ่งห้ามการขายการสุ่ม ตัดสินใจแล้วว่า
> **ขายการสุ่ม** เพราะเป็นช่องทางรายได้หลักช่องหนึ่ง เงื่อนไขที่ทำให้ยังซื่อสัตย์กับจุดขาย
> อยู่ได้ (รายละเอียดใน [12-summon-spec.md](12-summon-spec.md)):
>
> 1. สุ่มได้เฉพาะร่างขั้น 1 และเพดานเลเวลผูกกับขั้น evolve (`maxLevelByStage`) ไม่ใช่ rarity
>    — เงินซื้อ *สิทธิ์เข้าถึงสาย* ไม่ใช่พลังที่ปั้นเสร็จแล้ว
> 2. ยังห้ามขายสแตท วัตถุดิบ evolve ขั้นสูง หรือตัวละครขั้น II/III ตรง ๆ
> 3. อัตราทุกชั้นและตัวนับ pity แสดงบนหน้าจอเสมอ

## การซื้อในแอป

| เรื่อง | วิธีดำเนินการ |
| --- | --- |
| ซื้อในแอป | Unity IAP เชื่อม Apple/Google แล้วให้ backend ตรวจสอบ **ก่อน** จ่ายของ |
| ป้องกันของซ้ำ | รหัสธุรกรรมไม่ซ้ำ + บันทึกการจ่ายรางวัลแบบ idempotent |
| การซื้อค้าง | รับสถานะจาก store เมื่อเข้าเกมครั้งถัดไป และจ่ายของที่ค้าง |
| การคืนเงิน | รับ webhook จาก store แล้วปรับสิทธิ์หรือยอดคงเหลือตามนโยบายที่ประกาศไว้ |
| เปลี่ยนเครื่อง | คืนสิทธิ์และยอดตามประเภทสินค้าและกติกา store |

Google แนะนำให้ตรวจสอบการซื้อผ่าน backend และ AdMob รองรับการตรวจ callback
ของ rewarded ads ฝั่งเซิร์ฟเวอร์ (SSV) — **ห้ามเชื่อไคลเอนต์ในทั้งสองกรณี**

## โฆษณารับรางวัล

- ใช้ server-side verification callback เท่านั้น
- มีเพดานรายวันต่อบัญชี และเพดานต่อประเภทรางวัล
- รางวัลจากโฆษณาต้องไม่เกินสิ่งที่ผู้เล่นฟรีหาได้เองในเวลาที่สมเหตุสมผล

## ก่อนเปิดจริงต้องตรวจ

- ข้อกำหนด store เรื่องการซื้อ ความเป็นส่วนตัว และ **การลบบัญชี**
- การเปิดเผยโอกาสได้รับของ หากใช้การสุ่มที่มีการจ่ายเงิน
- นโยบายข้อมูลเด็กและการขอความยินยอมโฆษณาตามเขตพื้นที่

## ตัวเลขที่ต้องมีก่อนล็อกเอกสารนี้

จากระยะ C:

1. เวลาเฉลี่ยที่ผู้เล่นฟรีใช้เพื่อ evolve ตัวแรกถึงขั้น II
2. ทองและวัตถุดิบต่อชั่วโมงการฟาร์มในแต่ละด่าน
3. ผู้เล่นถึงเพดาน `inherited` 300 per-mille ได้เร็วแค่ไหน
4. สัดส่วนที่เวลาฟาร์มลดลงถ้าซื้อพลังสำรวจ

`simrunner sweep` ตอบข้อ 1–3 ได้โดยประมาณเมื่อวงจรฟาร์มมีตัวเลขจริงแล้ว
