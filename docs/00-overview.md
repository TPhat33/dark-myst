# Dark Myst — ภาพรวมและขอบเขตเวอร์ชันแรก

เกม 2D dark fantasy แนวจัดทีม–ต่อสู้–ฟาร์ม–evolve บนมือถือ (iOS + Android) โปรเจกต์ Unity ชุดเดียว
พร้อมระบบหลังบ้านที่ดูแลบัญชี ตัวละคร และเศรษฐกิจในเกม

เอกสารชุดนี้คือผลของ **ระยะ A (ล็อกแบบเกม)** ตามแผน: กฎชัดพอที่จะเขียนเป็นกรณีทดสอบได้
และในรีโปนี้กฎเหล่านั้นถูกเขียนเป็นเทสต์จริงแล้ว (`tests/`)

## จุดขายที่ยืนยันแล้ว

1. **ตัวละครที่น่าจดจำ** — ตัวละครแต่ละตัวมีตัวตนของตัวเอง ไม่ใช่แค่แถวตัวเลข
   ได้มาเมื่อไร ปั้นด้วยอะไร เคยกลายร่างมาแล้วกี่ครั้ง ล้วนถูกบันทึกไว้
2. **งานปั้นที่มีคุณค่า** — evolve ต้องรู้สึกคุ้ม และต้องอธิบายได้ว่าทำไมได้สแตทเท่านี้
3. **การจัดทีมมีผล** — เปลี่ยนทีมหรือเปลี่ยนตำแหน่งแล้วผลต่างอย่างเข้าใจได้

ข้อ 3 พิสูจน์ได้แล้วด้วย `simrunner sweep` และ `simrunner matrix` (ยืนยันว่าไม่มีทีมเดียวที่ชนะทุกที่
ไม่มีตัวละครที่ไม่มีที่ใช้ และทีมที่แพ้ยังมีทางกู้คืนด้วยการจัดทีมใหม่) — ดู [07-testing-plan.md](07-testing-plan.md)

## ขอบเขตเวอร์ชันแรก

| ส่วน | เวอร์ชันแรก | สถานะในรีโปนี้ |
| --- | --- | --- |
| การแสดงผล | แนวตั้ง ภาพ 2D Dark Fantasy | ยังไม่เริ่ม |
| ทีม | ผู้นำ 1 + สมาชิก 4 (5 ช่อง 2 แถว) | ✅ `Formation` |
| ต่อสู้ | อัตโนมัติหลังจัดทีม เห็นลำดับสกิลและผลของตำแหน่ง | ✅ `DarkMyst.Combat` |
| ตัวละคร | 12–16 สายตัวละคร | ✅ 14 สาย / 19 ร่าง |
| สกิล | กลไกหลัก 8–10 ประเภท | ✅ 11 `EffectKind` / 7 `TriggerKind` |
| เนื้อเรื่อง | บทเปิดที่จบเป็นตอน มีบอส | ยังไม่เริ่ม |
| สำรวจ | แผนที่จุดเชื่อม มีทางเลือกและบัฟเฉพาะรอบ | ✅ `DarkMyst.Expedition` — ด่านต้นแบบ `stg_ashfields` |
| การปั้น | เลเวล สกิล evolve และแนวทางเน้นสแตท | ✅ `Progression` / `Evolution` |
| Community | แชร์ตัวละคร สูตรทีม และประวัติการปั้น | ยังไม่เริ่ม |
| รายได้ | แพ็กเริ่มต้น วัตถุดิบจำกัด และ rewarded ads | ยังไม่เริ่ม (ดู [04](04-economy-spec.md)) |
| การแข่งขัน | สนามฝึกก่อน แล้วค่อย PvP แบบ async | ยังไม่เริ่ม |

**ยังไม่ทำในเวอร์ชันแรก:** ตลาดซื้อขายตัวละคร, กิลด์วอร์, PvP สด, การกดสกิลระหว่างสู้

ข้อมูลตัวละครถูกออกแบบให้มีตัวตนและประวัติชัดเจนตั้งแต่ต้น (`OwnedCharacter.InstanceId`
ไม่เคยถูกใช้ซ้ำแม้ตัวละครถูกใช้เป็นวัตถุดิบไปแล้ว) เพื่อไม่ปิดทางการแลกเปลี่ยนในอนาคต

ระบบพันธสัญญาเริ่มจากสกิลสัมพันธ์ไม่กี่แบบก่อน — ในเวอร์ชันนี้ทำได้ด้วยข้อมูลล้วน
โดยใช้ `IsLeaderSkill` + `TriggerKind.OnAllyDown` ยังไม่ต้องเขียนโค้ดเพิ่ม

## ทำไมเลือก Unity + C# ทั้งสองฝั่ง

Unity รองรับ iOS และ Android จากโปรเจกต์เดียว มี editor ให้จัดฉากและดูผลทันที
และมี Unity IAP สำหรับเชื่อมการซื้อในแอป — สำคัญเมื่อเราต้องทำตัวละครเคลื่อนไหว เอฟเฟกต์สกิล
และการเปลี่ยนร่างต่อเนื่องระยะยาว

เหตุผลที่หลังบ้านเป็น C# ด้วย ไม่ใช่ Node/TS ที่คุณคุ้นกว่า: **กฎการต่อสู้และสูตร evolve
ต้องใช้โค้ดชุดเดียวกันทั้งสองฝั่ง** หน้าจอ preview สแตทก่อน evolve ที่ไม่ตรงกับผลจริง
คือวิธีที่เร็วที่สุดในการทำลายความเชื่อมั่นในเกมที่สร้างบนการฟาร์ม
ส่วนหน้าจัดการเนื้อหาและเครื่องมือยังใช้ TS/Vue ได้ตามที่ถนัด

## ลำดับการทำงาน

ล็อกกฎการต่อสู้และ evolve → ต้นแบบบนมือถือสองระบบ → วงจรฟาร์มและเนื้อเรื่องให้เล่นครบ
→ จึงเพิ่มระบบออนไลน์และรายได้

milestone แรกคือผู้เล่นพูดได้ว่า *"อยากกลับไปปั้นตัวนี้ต่อ"* ก่อนขยายจำนวนตัวละครและขนาดโลก
รายละเอียดใน [06-roadmap.md](06-roadmap.md)
