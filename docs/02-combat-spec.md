# กฎการต่อสู้ — เวอร์ชัน 1.0.0

เอกสารนี้คือความจริงของระบบต่อสู้ ทุกข้อในนี้มีเทสต์รองรับใน
`tests/DarkMyst.Combat.Tests/` การแก้ตัวเลขใด ๆ ต้องขึ้น `CombatRules.Version`

## หลักการ

ระบบคำนวณ **แยกจากภาพโดยสิ้นเชิง** รับข้อมูลเข้า → ส่งลำดับเหตุการณ์ออก
Unity นำเหตุการณ์มาแสดงภาพ จึงเร่งความเร็ว เล่นซ้ำ และตรวจเหตุผลที่แพ้ได้
**โดยความเร็วแอนิเมชันไม่มีทางเปลี่ยนผลการต่อสู้** เพราะผลถูกคำนวณจบก่อนภาพจะเริ่มเล่น

ข้อมูลเข้า (`BattleRequest`): ทีมทั้งสองฝั่ง ตำแหน่ง สแตท สกิล, seed, เวอร์ชันกฎ, เวอร์ชันเนื้อหา
ข้อมูลออก (`BattleResult`): ลำดับเหตุการณ์, ผลแพ้ชนะ, สถานะสุดท้าย, จำนวนครั้งที่สุ่ม, checksum

## ความแน่นอนของผล (determinism)

เกมที่ให้รางวัลจริงต้องใช้ผลที่เซิร์ฟเวอร์ตรวจสอบได้ ดังนั้น request เดียวกันต้องให้ผลเดียวกัน
บนทุกแพลตฟอร์ม ตลอดไป มาตรการที่ใช้:

| มาตรการ | เหตุผล |
| --- | --- |
| เลขจำนวนเต็มล้วน ค่าอัตราส่วนเก็บเป็น per-mille (1000 = 100%) | `float` ให้ผลต่างกันได้ระหว่าง IL2CPP กับ .NET บนเซิร์ฟเวอร์ |
| `DeterministicRandom` (PCG-XSH-RR 32-bit) | `System.Random` ไม่ระบุอัลกอริทึม และเปลี่ยนตามเวอร์ชัน .NET |
| ลำดับวนซ้ำคงที่เสมอ (ฝั่ง แล้วช่อง) | ลำดับของ `Dictionary` ไม่รับประกัน |
| `RngCalls` ติดมากับผล | ถ้าสองฝั่งได้ผลเท่ากันแต่จำนวนการสุ่มต่างกัน แปลว่ากฎเริ่มเพี้ยนแล้ว |
| `Checksum` (FNV-1a 64 บน log) | เทียบสตริงเดียวก็รู้ว่า log ตรงกันไหม |

`Chance(perMille)` ที่ 1000 หรือ 0 **ไม่กิน RNG** เพื่อให้สกิลรับประกันไม่ขยับ stream

## สนามรบ

5 ช่องต่อฝ่าย: ช่อง **0–1 คือแถวหน้า**, ช่อง **2–4 คือแถวหลัง**
ผู้นำคือหน่วยที่อยู่ในช่อง `LeaderSlot` — สกิลที่ติดธง `IsLeaderSkill` ทำงานเฉพาะเมื่ออยู่ช่องนั้น

## สแตท

`MaxHp`, `Attack`, `Magic`, `Defense`, `Resist`, `Speed`, `CritRate` (per-mille), `CritDamage` (per-mille)

**`MaxHp` แก้ด้วยบัฟระหว่างสู้ไม่ได้ในเวอร์ชันนี้** — การเปลี่ยนขนาดถังเลือดกลางเกม
ทำให้เกิดคำถามว่าเลือดปัจจุบันควรขยับตามไหม ซึ่งยังไม่คุ้มจะตอบ

บัฟ/ดีบัฟบวกกันแบบ per-mille แล้วจึงตัดที่ **[-750, +1500]** ก่อนคูณกับค่าฐาน
เพดานกันไม่ให้บัฟซ้อนจนตัวเลขอ่านไม่รู้เรื่อง พื้นกันไม่ให้ดีบัฟซ้อนจนสแตทเป็นศูนย์

## ธาตุ (Affinity)

```
Ember → Verdant → Tide → Ember        (วงสามเหลี่ยม)
Radiant ↔ Umbral                       (แรงใส่กันทั้งคู่)
Neutral                                (ไม่ได้เปรียบและไม่เสียเปรียบกับใคร)
```

ได้เปรียบ ×1.25 / เสียเปรียบ ×0.80

## สูตรความเสียหาย

ลำดับการคูณเป็นส่วนหนึ่งของสัญญา — การหารจำนวนเต็มตัดเศษ การสลับลำดับจึงเปลี่ยนผลลัพธ์

```
raw        = attack × power / 1000
mitigated  = raw × K / (defense + K)            K = 300
afterRow   = mitigated × row / 1000
afterAff   = afterRow × affinity / 1000
afterCrit  = afterAff × crit / 1000
damage     = max(1, afterCrit × variance / 1000)
```

| ตัวแปร | ค่า |
| --- | --- |
| `K` | 300 — ที่ defense 300 ลดความเสียหายลงครึ่งหนึ่ง |
| `row` | กายภาพ: แถวหน้า 1100, แถวหลัง 900 · เวทและ True: 1000 |
| `crit` | ปกติ 1000 · คริ 1500 + `CritDamage` ของผู้โจมตี |
| `variance` | สุ่ม 950–1050 |

- **Physical** คูณจาก `Attack` ลดด้วย `Defense` และได้รับผลจากแถว
- **Magical** คูณจาก `Magic` ลดด้วย `Resist` **ไม่สนใจแถว** — เวทจึงเป็นคำตอบของทีมที่ซ่อนตัวแบกไว้หลัง
- **True** ข้ามการลดทอน แถว และธาตุทั้งหมด ใช้กับพิษและสกิลสะท้อน

ความเสียหายต่ำสุดคือ 1 เสมอ ผู้โจมตีที่โดนไล่สแตทไปไกลยังกัดได้ทีละนิด

## ลำดับการกระทำ

คำนวณใหม่ทุกต้นรอบ เรียงตาม `Speed` มากไปน้อย เสมอกันตัดสินด้วย (ฝั่ง แล้วช่อง)
**ไม่ใช้การสุ่ม** เพราะสองทีมที่เหมือนกันเป๊ะก็ยังต้องได้ log ที่ทำซ้ำได้

การบัฟความเร็วจึงมีผลตั้งแต่รอบถัดไป ไม่ใช่รอบปัจจุบัน

## รอบหนึ่งรอบ

1. `RoundStarted`
2. คำนวณลำดับการกระทำจากหน่วยที่ยังยืนอยู่
3. ยิง `OnRoundStart` ตามลำดับนั้น
4. แต่ละหน่วยเข้าตา:
   - ถ้าถูกสตัน → ลดตัวนับสตัน, ได้ภูมิคุ้มกัน, `TurnSkipped`
   - ยิง `OnBeforeAction`
   - เลือกสกิล: ไล่สกิล `OnAction` **ตามลำดับที่เขียนในเนื้อหา** เลือกอันแรกที่คูลดาวน์หมดและสุ่มติด
   - ใช้สกิล
   - ถ้ามีภูมิคุ้มกันสตันเหลือ ลดลง 1
5. ปลายรอบ: **HoT ทำงานก่อน แล้วจึง DoT** ตามลำดับการกระทำ
6. ลดอายุสถานะ โล่ และคูลดาวน์ · สถานะที่หมดอายุถูกถอด
7. `RoundEnded`

ข้อ 5 ถูกกำหนดไว้ชัดเจน ไม่ใช่เกิดขึ้นเอง: หน่วยที่มีเลือด 100 มี regen 200 และพิษ 250
จะรอดรอบนั้น

การเลือกสกิลไล่ตามลำดับที่เขียน ทำให้เนื้อหาอ่านจากบนลงล่างว่า
*"ใช้อันนี้ถ้าได้ ไม่งั้นอันนี้ ไม่งั้นโจมตีธรรมดา"* ซึ่งตรงกับวิธีคิดของนักออกแบบอยู่แล้ว

**ทุกหน่วยต้องมีสกิล `OnAction` ที่รับประกัน 100% และไม่มีคูลดาวน์อย่างน้อยหนึ่งอัน**
ทั้ง `BattleSimulator` และ `ContentPack.Validate()` ปฏิเสธเนื้อหาที่ผิดข้อนี้ ไม่งั้นหน่วยนั้น
อาจยืนเฉยทั้งตาโดยไม่มีใครรู้ว่าทำไม

## การเลือกเป้าหมาย

| ตัวเลือก | พฤติกรรม |
| --- | --- |
| `Self` / `TriggerSource` | ตัวเอง / หน่วยที่ทำให้ trigger ทำงาน |
| `RandomEnemy` / `RandomAlly` | สุ่มไม่ซ้ำ `MaxTargets` ตัว |
| `FrontRowEnemy` | สุ่มจากแถวหน้า — **ถ้าแถวหน้าล้มหมด ตกไปที่แถวหลัง** |
| `LowestHpEnemy` / `LowestHpAlly` | เลือดน้อยสุด เสมอกันตัดที่ช่องน้อยกว่า |
| `HighestAttackEnemy` | `Attack` สูงสุดหลังบัฟ เสมอกันตัดที่ช่องน้อยกว่า |
| `AllEnemies` / `AllAllies` | ทุกหน่วยที่ยังยืนอยู่ |
| `LowestSlotDownedAlly` | หน่วยที่ล้มแล้วซึ่งช่องน้อยที่สุด — ใช้กับการชุบชีวิต |

**Taunt** บังคับให้สกิลเป้าหมายเดี่ยวที่เล็งศัตรูต้องเลือกเฉพาะหน่วยที่ยั่วยุ
ยกเว้นเมื่อ effect ติดธง `IgnoresTaunt` หรือเป็น `AllEnemies`

> **ข้อควรระวังของผู้เขียนเนื้อหา:** effect แต่ละอันในสกิลเดียวกัน **เลือกเป้าหมายของตัวเอง**
> สกิลที่ตีแล้วติดพิษด้วย `LowestHpEnemy` อาจติดพิษคนละตัวกับที่ตี ถ้าอยากให้แน่นอน
> ให้ใช้ `TargetSelector` ที่เจาะจง หรือรวมเป็น effect เดียว

## กลไกของสกิล (`EffectKind`)

| กลไก | ตัวแปรที่แก้ได้ในเนื้อหา |
| --- | --- |
| `Damage` | สแตทที่ใช้คูณ, ตัวคูณ, จำนวนครั้ง, คริได้ไหม, ดูดเลือด, ทะลุ taunt |
| `Heal` | สแตทที่ใช้คูณ, ตัวคูณ, ค่าคงที่ |
| `StatModifier` | สแตทที่เปลี่ยน, ขนาด, ระยะเวลา, การซ้อน |
| `DamageOverTime` | ความเสียหายต่อ tick, ระยะเวลา, จำนวนชั้น |
| `HealOverTime` | การฟื้นฟูต่อ tick, ระยะเวลา |
| `Shield` | ขนาดโล่, ระยะเวลา |
| `Cleanse` / `Dispel` | ถอดดีบัฟ / ถอดบัฟ, จำนวนที่ถอด |
| `Taunt` | ระยะเวลา |
| `Stun` | ระยะเวลา, โอกาสติด |
| `Revive` | สัดส่วนเลือดที่ฟื้น |

DoT และ HoT **บันทึกค่าต่อ tick ตอนที่ติดสถานะ** จากสแตทของผู้ร่าย บัฟที่มาทีหลัง
ไม่ย้อนไปเปลี่ยนค่า — ทำให้คำถาม *"ทำไมโดนพิษ 340"* ตอบได้จาก log

การซ้อนสถานะ (`StackRule`):

| กติกา | พฤติกรรม |
| --- | --- |
| `Refresh` | เหลือชิ้นเดียว รีเซ็ตเวลา เก็บขนาดที่แรงกว่า |
| `Stack` | เหลือชิ้นเดียว เพิ่มชั้นจนถึง `MaxStacks` รีเซ็ตเวลา |
| `Ignore` | คงของเดิม ทิ้งอันใหม่ |
| `Independent` | เก็บเป็นชิ้นใหม่ มีอายุของตัวเอง |

`Cleanse` ถอดเฉพาะสถานะที่เป็นโทษ `Dispel` ถอดเฉพาะที่เป็นคุณ — ตัดสินจากชนิดของ effect
และเครื่องหมายของ `AmountPerMille`

## โล่ ความตาย และการชุบชีวิต

- โล่ดูดซับก่อนเลือด ใช้อันที่เก่าที่สุดก่อน และรายงานเป็น `ShieldAbsorbed` แยกจาก `Damaged`
- เลือดถึง 0 → `UnitDowned` → ยิง `OnDeath` ของหน่วยนั้น → **ล้างสถานะและโล่ทั้งหมด**
  → ยิง `OnAllyDown` ให้เพื่อนที่ยังยืนอยู่
- ชุบชีวิตคืนเลือดตามสัดส่วนของ `MaxHp` และได้สถานะว่างเปล่า
- **หน่วยที่ถูกชุบไม่ได้ลงมือในรอบนั้น** เพราะลำดับการกระทำถูกล็อกตั้งแต่ต้นรอบ

## Trigger

`OnBattleStart`, `OnRoundStart`, `OnBeforeAction`, `OnAction`, `OnAfterDamaged`,
`OnAllyDown`, `OnDeath`

ปฏิกิริยาซ้อนกันได้ลึกสุด `MaxReactionDepth` = 2 — นี่คือสิ่งที่หยุดสกิลสวนกลับสองตัว
ไม่ให้ตีกันไปมาไม่รู้จบ `OnDeath` เป็น trigger เดียวที่หน่วยซึ่งล้มแล้วยังได้ใช้

## สตันและภูมิคุ้มกัน

ภูมิคุ้มกันสตัน **หมดอายุด้วยการได้ลงมือ ไม่ใช่ด้วยเวลา** ที่ค่า 1
หน่วยหนึ่งจะถูกสตันได้อย่างมากทุกตาเว้นตา

ถ้านับเป็นรอบแทน ผู้ร่ายที่ลงมือก่อนเหยื่อจะสตันซ้ำได้ก่อนภูมิคุ้มกันจะได้กันอะไรเลย —
เป็นบั๊กที่เจอตอนเขียนเทสต์ข้อนี้ ไม่ใช่ตอนออกแบบ

## การจบการต่อสู้

- ฝ่ายใดล้มหมด → อีกฝ่ายชนะ
- ครบ 30 รอบ → เทียบ **สัดส่วนเลือดที่เหลือ** ฝ่ายที่มากกว่าชนะ
- เท่ากันพอดี → เสมอ (`Draw`) — ระบบรอบนอกเป็นผู้ตัดสินว่าเสมอมีค่าเท่าไร
  ใน PvE ให้ถือว่าฝ่ายบุกแพ้

## ลำดับเหตุการณ์ (`BattleEvent`)

```
BattleStarted, RoundStarted, TurnStarted, TurnSkipped, SkillActivated,
Damaged, Healed, ShieldAbsorbed, StatusApplied, StatusRefreshed, StatusResisted,
StatusTicked, StatusExpired, StatusRemoved, UnitDowned, UnitRevived,
TurnEnded, RoundEnded, BattleEnded
```

`StatusResisted` ถูกบันทึกด้วยเจตนา เพื่อให้ตอบผู้เล่นได้ว่า *"ทำไมพิษไม่ติด"*

แต่ละเหตุการณ์อ้างถึงหน่วยด้วย `UnitRef` (ฝั่ง + ช่อง) ไม่ใช่ตัวอ้างอิงวัตถุ
จึง serialize ได้และยังใช้ได้แม้หน่วยนั้นล้มไปแล้ว

## สิ่งที่ยังไม่ทำและผลของมัน

ในเวอร์ชันแรกผู้เล่นตัดสินใจ **ก่อนการต่อสู้และระหว่างจุดสำรวจ** เท่านั้น
หากภายหลังพบว่าต้องมีการกดสกิลระหว่างสู้ จะต้องเพิ่ม:

- ช่องทางรับคำสั่งระหว่างรอบ และการตรวจสอบลำดับคำสั่งฝั่งเซิร์ฟเวอร์
- การจัดการกรณีเน็ตหลุดกลางการต่อสู้
- การเล่นซ้ำที่รวมคำสั่งของผู้เล่นไว้ใน log ด้วย

ทั้งสามข้อมีต้นทุนจริง จึงควรตัดสินใจจากผลทดสอบระยะ B ไม่ใช่จากความรู้สึก
