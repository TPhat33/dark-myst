## การจัดทีมมีผลจริงไหม — วัดแล้ว

เกณฑ์ผ่านของระยะ B คือ *"เปลี่ยนทีมแล้วผลต่างอย่างเข้าใจได้"* ซึ่งวัดได้ ไม่ใช่แค่รู้สึกเอา
รันกับบอสที่เลเวลโรสเตอร์ 12 ครั้งละ 300 seed:

| ทีม | อัตราชนะ |
| --- | --- |
| Knight, Warden, Adept, Oracle, Stalker (แทงก์หน้า หมอหลัง) | **89%** |
| Adept, Stalker, Knight, Warden, Oracle (เอาตัวบางขึ้นหน้า) | **80%** |
| Knight, Warden, Maiden, Hexer, Stalker (ไม่มีหมอ) | **0%** |

อ่านได้ว่า: ตำแหน่งมีผลจริงแต่ไม่ถึงกับชี้ขาด ส่วนการไม่มีตัวฮีลเลยคือแพ้ขาด
นี่คือรูปร่างที่ต้องการ — ตัดสินใจผิดแล้วเจ็บ แต่ยังกู้คืนได้ด้วยการปรับทีม

## ความหลากหลายของโรสเตอร์ 14 สาย — วัดแล้วด้วย `simrunner matrix`

เมื่อโรสเตอร์ขยายเป็น 14 สาย คำถามในหัวข้อ "สมดุล" ของแผนทดสอบ (ทีมยอดนิยมมีตัวแก้ทาง
ส่วนต่างสแตทไม่ทำให้หมดโอกาส) ตอบได้จริงและต้องตอบ สามข้อที่วัด ทุกข้อรันที่ 300 seed
ต่อช่อง (ยืนยันด้วย seed เริ่มต้นอีกชุดหนึ่งแล้วภาพรวมไม่เปลี่ยน — ตัวเลขต่างกันไม่เกิน ~3-4%
ตามที่คาดจากขนาดตัวอย่าง):

```bash
dotnet run --project tools/DarkMyst.SimRunner -- matrix --level 12 --repeat 300 \
  --rosters "core_balanced=chr_ashen_knight_i,chr_grave_warden_i,chr_ember_adept_i,chr_tide_oracle_i,chr_pale_stalker_i;swap_shackleborn=chr_ashen_knight_i,chr_grave_warden_i,chr_shackleborn_i,chr_tide_oracle_i,chr_pale_stalker_i"

# หรือเก็บโรสเตอร์หลายชุดไว้ในไฟล์บรรทัดละ "ชื่อ=id,id,id,id,id" แล้วอ้างด้วย --rosters-file
```

### 1. ไม่มีทีมเดียวที่ครองเกม

รันทีมฐาน (Ashen Knight, Grave Warden, Ember Adept, Tide Oracle, Pale Stalker — ทีม 89%
เดิม) สลับทีละช่องด้วยแต่ละสายใหม่ทั้ง 6 สาย เทียบกับ `enc_boss_ashen_revenant` ที่เลเวล 12
(ด่านเดียวใน 4 ด่านที่ยังไม่ชนะ 100% ที่เลเวลนี้ อีกสามด่านชนะ 100% ทุกทีมอยู่แล้วจึงไม่มีอะไรให้วัด):

| ทีม (สลับหนึ่งช่องจากทีมฐาน) | อัตราชนะ (boss lv12) |
| --- | --- |
| ทีมฐาน (ไม่สลับ) | 89.0% |
| → Bramble Warden แทน Grave Warden | 89.3% |
| → Riptide Stormcaller แทน Ember Adept | 93.0% |
| → Dawnrider เป็นผู้นำแทน Ashen Knight | 89.3% |
| → Ashfield Reaver แทน Grave Warden | 85.3% |
| → Hollow Warder แทน Grave Warden | 88.0% |
| → Shackleborn แทน Ember Adept | **95.3%** |
| → Mire Hexer แทน Ember Adept | 65.0% |
| → Dawn Cantor แทน Tide Oracle | 86.7% |
| → Thorn Maiden แทน Pale Stalker | 78.7% |

ไม่มีทีมไหนแตะ 100% ที่เลเวลแนะนำ แม้แต่ทีมที่รวมช่องที่แรงที่สุดสองช่องเข้าด้วยกัน
(Shackleborn + Riptide Stormcaller พร้อมกัน) ก็ยังแพ้ 5.0% ที่ lv12 และแพ้เกินครึ่งที่ lv8
(30.0%) — เส้นความยากยังจริงแม้กับทีมที่ตั้งใจสร้างให้แรงที่สุดเท่าที่คิดออก

`Shackleborn` (95.3%) เป็นตัวที่ใกล้ "ครองเกม" ที่สุด เพราะสตันล็อกสกิลไม้ตายของบอส
(`skl_revenant_wrath`, คูลดาวน์ 1, โจมตีทั้งทีม) ได้บ่อยกว่า Stunning Blow เดิม (650 ต่อ 450
ต่อมิลล์) แต่ยังแพ้เกือบ 1 ใน 20 ครั้ง และเลเวลต่ำกว่าแนะนำก็ยังแพ้เป็นส่วนใหญ่ — **ตัดสินใจ:
ไม่ต้องลดพลัง** ปล่อยให้เป็นตัวเลือกที่แข็งแกร่งของบทบาท "ตัวคุมสถานะ" ต่อไป เพราะยังไม่ถึงระดับ
"ไม่มีความเสี่ยงเหลือ" ที่นิยามไว้ว่าเป็นบั๊ก

### 2. ไม่มีตัวละครที่ไม่มีที่ใช้

ตารางข้างบนคือหลักฐานส่วนหนึ่งอยู่แล้ว: ทุกการสลับยังชนะเป็นส่วนใหญ่ (65%-95.3%) ไม่มีสายไหน
ที่สลับเข้าไปแล้วทีมพังทั้งยวง สำหรับสายใหม่ทั้ง 6 ยังหาจุดที่ **ดีกว่าตัวที่มันแทนที่** ได้ชัดเจน
(ไม่ใช่แค่ "ยังพอใช้ได้"):

| สาย | จุดที่มันทำได้ดีกว่าใครอื่น | ตัวเลข |
| --- | --- | --- |
| Bramble Warden | แท้งค์ Resist ตัวที่สองของ Verdant — สู้บอสธาตุเวทล้วน (`enc_warlock_conclave`) ได้ดีกว่าแท้งค์ Defense เดิมชัดเจน | สลับ Ashen Knight → Bramble Warden ที่ lv4: **79.0% → 98.7%** |
| Riptide Stormcaller | ทำลาย Resist ศัตรูเป็นวงกว้าง ช่วยทีมที่เหลือ (รวมถึงสกิลเวทของตัวเอง) ต่อสู้บอสที่มี Resist สูง (175) | สลับ Ember Adept → Stormcaller ที่บอส lv12: **89.0% → 93.0%** |
| Dawnrider | บัฟ Speed ทั้งทีมจากผู้นำ — กลไกที่ไม่มีสายไหนในโรสเตอร์ทำมาก่อน (ผู้นำสายอื่นบัฟ Attack หรือ Defense เท่านั้น) | ดูหมายเหตุด้านล่าง — ผลวัดได้ไม่ชัดเท่าห้าสายที่เหลือ |
| Ashfield Reaver | โจมตีกายภาพเป็นวงกว้าง (ไม่มีใครโจมตีกายภาพครบทุกตัวได้มาก่อน) ได้เปรียบเมื่อศัตรูมาเป็นฝูง | สลับ Ember Adept → Reaver ที่ `enc_crypt_patrol` lv4: **40.0% → 43.0%** |
| Hollow Warder | ตัวเลือกแท้งค์สำรองที่ลดคริติคอลของศัตรูทั้งทีม แทน Grave Warden ได้แทบไม่เสียอะไร | สลับ Grave Warden → Hollow Warder ที่บอส lv12: 89.0% → **88.0%** (ต่างกันในช่วงคลาดเคลื่อนของการสุ่ม) |
| Shackleborn | ตัวคุมสถานะที่สตันได้แม่นกว่า Stunning Blow เดิม | สลับ Ember Adept → Shackleborn ที่บอส lv12: 89.0% → **95.3%** |

สายเดิมสามสายที่เอกสารรุ่นก่อนไม่เคยแสดงในทีมชนะเลย (Thorn Maiden, Mire Hexer, Dawn Cantor)
ก็ตรวจแล้วเช่นกัน — Thorn Maiden ทำได้ **ดีกว่า** Ember Adept ในด่านฝูงศัตรูเลเวลต่ำ (สลับ
Pale Stalker → Thorn Maiden ที่ `enc_crypt_patrol` lv4: ทีมฐาน 40.0% ต่อทีมที่มี Thorn Maiden
46.3% — พิษสะสมได้ประโยชน์จากไฟต์ที่ยาวกว่า) Mire Hexer ยังพาให้ทีมชนะ
65% ที่ด่านบอส (จุดแข็งจริงของมันคือลด Defense ศัตรู ซึ่งช่วยหน่วยกายภาพ ไม่ใช่หน่วยเวท —
การทดสอบแบบสลับหนึ่งช่องที่เอาหน่วยเวทออกจึงวัดจุดแข็งนี้ไม่ตรงนัก แต่ก็ไม่ใช่ "ไม่มีที่ใช้")

**หมายเหตุเรื่อง Dawnrider:** เป็นสายเดียวที่ยังหาแมตช์อัพที่ "ดีกว่าอย่างชัดเจน" ไม่ได้ในรอบนี้
ลองสลับเป็นผู้นำแทน Ashen Knight แล้ววัดกับ `enc_warlock_conclave` (มี Wailing Wisp เร็ว 130 —
ด่านที่น่าจะได้ประโยชน์จาก Speed buff ที่สุด) ที่ lv2/3/4: **18.7%/46.7%/70.7%** ต่อ Ashen
Knight leader **14.0%/46.0%/79.0%** — lv2 ดีกว่าเล็กน้อย, lv3 แทบไม่ต่าง, lv4 แย่กว่า (เสีย
taunt ของ Ashen Knight ไปมีผลมากกว่าที่ Speed buff ได้คืนมาในไฟต์ที่ยาว ~9 รอบโดยเฉลี่ย)
ที่บอสหลัก (จุดวัดหลักของหัวข้อนี้) ผลอยู่ที่ 89.3% ทั้งสองรอบ seed ที่วัด — **เท่ากับทีมฐานพอดี
ไม่ใช่แย่กว่า** จึงยังไม่ใช่ "ไม่มีที่ใช้" (ไม่มีตรงไหนที่แทนแล้วทีมพัง) แต่ก็ไม่มีแมตช์อัพไหนในเนื้อหา
ชุดนี้ที่พิสูจน์ว่ากลไกบัฟ Speed คุ้มค่ากว่าอย่างเด่นชัด — บันทึกไว้ตรง ๆ ว่าเป็นจุดที่วัดได้ไม่ชัด
ไม่ใช่ปกปิด: กลไกนี้น่าจะสำคัญกว่านี้กับด่านในอนาคตที่ออกแบบให้ "ใครลงมือก่อนตัดสินผล" ชัดกว่านี้
(เช่นบอสที่ตายเร็วถ้าโดนก่อน) ซึ่งชุดด่านปัจจุบันยังไม่มีแบบนั้น

**พบและแก้บั๊กสมดุลจริงหนึ่งจุดระหว่างการวัดนี้ (สายเดิม ไม่ใช่สายใหม่):** `chr_dawn_cantor_i`
เดิมเป็น "ตัวละครที่ไม่มีที่ใช้" จริง ๆ — สลับเข้าแทน Tide Oracle แล้วทีมฐานร่วงจาก 89% เหลือ
**7.3%** ที่บอส (และ 2.7% ทั้งด่านสำรวจ) สาเหตุ: `skl_dawn_aegis` ของมันให้โล่กับพันธมิตร
**หนึ่งคน** ต่อครั้ง ขณะที่ `skl_tidal_hymn` ของ Tide Oracle ฟื้นฟูทั้งทีมทุกรอบ — ไม่ใช่ความ
แตกต่างของสไตล์ที่ตั้งใจ แต่เป็นช่องว่างพลังที่ห่างเกินไปสำหรับสายที่ควรเป็นทางเลือกคู่ขนานกัน
แก้ด้วยข้อมูลล้วน: เปลี่ยนเป้าหมายของ Dawn Aegis จาก `LowestHpAlly` เป็น `AllAllies` และลด
`amountPerMille` จาก 1400 เป็น 1200 เพื่อชดเชยที่ตอนนี้โล่ลงทั้งทีม หลังแก้: 89% → **86.7%**
ที่บอส, 57.0% → **58.0%** ที่ด่านสำรวจเต็ม — ใกล้เคียงทีมฐานจนเป็นทางเลือกที่แท้จริง ไม่ใช่
ตัวเลือกที่แย่กว่าเสมอ (ที่ `enc_crypt_patrol` lv4-5 ตอนนี้ Dawn Cantor ยังทำได้ **ดีกว่า** Tide
Oracle เสียอีก: 70.3%/91.0% ต่อ 40.0%/67.7%) การแก้นี้ไม่แตะ `chr_tide_oracle_i` หรือสายอื่น
เลย (`skl_dawn_aegis` มีสายเดียวที่ใช้) และไม่เปลี่ยนเส้นความยากของด่านมาตรฐาน (โรสเตอร์
ค่าเริ่มต้นของ `simrunner` ใช้ Tide Oracle ไม่ใช่ Dawn Cantor — ตัวเลขเส้นความยากทั้งหมด
ด้านล่างเหมือนเดิมทุกประการ)

พบอีกจุดที่อ่อนกว่าที่ควร (ไม่ถึงกับ "ไม่มีที่ใช้" แต่แก้ให้ดีขึ้น): `chr_hollow_warder_i`
ตอนแรกเมื่อสลับแทน Grave Warden ให้ 79.3% (ต่ำกว่าทีมฐานเกินสมควรสำหรับ "ตัวเลือกแท้งค์
คู่ขนาน") ปรับ Attack/Defense พื้นฐานขึ้นเล็กน้อยและเพิ่ม `amountPerMille` ของโล่ใน
`skl_nullshroud` จาก 900 เป็น 1500 — หลังแก้ได้ **88.0%** ใกล้ทีมฐานพอจะเป็นทางเลือกที่จับต้อง
ได้จริง

### 3. ทีมที่แพ้ยังกู้คืนได้ — แต่ต้องแก้ที่จุดถูก ไม่ใช่แก้อะไรก็ได้

ทีมอ้างอิงจากหัวข้อก่อนหน้า (Knight, Warden, Maiden, Hexer, Stalker — ไม่มีตัวฮีลเลย)
แพ้ 0.0% ที่บอส lv12 ทดสอบการกู้คืนสามแบบ:

| การเปลี่ยนทีม | อัตราชนะ (boss lv12) |
| --- | --- |
| ไม่เปลี่ยนอะไร (ทีมเดิม) | 0.0% |
| สลับ Mire Hexer → Tide Oracle (เพิ่มตัวฮีล) | **87.0%** |
| สลับ Mire Hexer → Dawn Cantor (เพิ่มตัวฮีลอีกสาย) | **82.3%** |
| สลับ Thorn Maiden → Bramble Warden (เพิ่มแท้งค์ตัวที่สาม แต่ยังไม่มีตัวฮีล) | 0.0% |
| ไม่เปลี่ยนทีม แต่เลี้ยงให้ถึงเพดานเลเวลด่าน 1 (lv20) แทน | 65.3% |

อ่านได้ตรงกับที่ต้องการพิสูจน์: การแพ้ครั้งนี้ **กู้คืนได้จริง** แต่กู้คืนได้ด้วยการแก้ปัญหาที่ถูกจุด
(เพิ่มตัวฮีลตัวไหนก็ได้ในสองสายที่มี) ไม่ใช่การเปลี่ยนแปลงทีมแบบใดก็ได้ (เพิ่มแท้งค์ตัวที่สามไม่ช่วย
เลย) และ **ส่วนต่างสแตทเพียงอย่างเดียวไม่พอ**: เลี้ยงทีมเดิมที่ไม่มีตัวฮีลไปจนถึงเพดานเลเวลของ
ร่างแรก (lv20) ให้ผลแค่ 65.3% — ยังห่างจากทางแก้ที่ถูกจุดที่ทำได้ 82-87% ตั้งแต่ lv12 (เลเวล
แนะนำ) แปลว่าการจัดทีมพาไปได้ไกลกว่าการไล่เลเวลเฉย ๆ — สมกับที่จุดขายข้อ 3 ต้องการพิสูจน์

## เส้นความยาก — วัดแล้วเช่นกัน

อัตราชนะตามเลเวลของทีม (300 seed ต่อช่อง):

| ด่าน | lv1 | lv4–5 | lv8–10 | lv16+ |
| --- | --- | --- | --- | --- |
| `enc_tutorial_hounds` | 100% | 100% | 100% | 100% |
| `enc_crypt_patrol` | 0% | 40% | 100% | 100% |
| `enc_boss_ashen_revenant` | 0% | — | 56% (lv10) | 100% |
| `enc_warlock_conclave` | 1% | 79% (lv4) | 100% | 100% |

ด่านสอนต้องชนะเสมอ ด่านฟาร์มเปิดประมาณเลเวล 4–8 บอสเปิดประมาณเลเวล 10–16
นี่คือเหตุผลที่ผู้เล่นต้องกลับไปฟาร์ม

`enc_warlock_conclave` คือด่านใหม่: ศัตรูทั้งด่านโจมตีด้วยเวทล้วน (ไม่มีหน่วยกายภาพเลย) —
เพิ่มมาเพื่อให้มีสนามที่พิสูจน์ได้ว่าแท้งค์สาย Resist (Bramble Warden) กับตัวทำลาย Resist
(Riptide Stormcaller) มีที่ใช้จริง เพราะสามด่านเดิมไม่มีด่านไหนกดดัน Resist ล้วน ๆ
ขนาดนี้มาก่อน (ดูหัวข้อความหลากหลายของโรสเตอร์ด้านบน)

ทำซ้ำได้ด้วย:

```bash
dotnet run --project tools/DarkMyst.SimRunner -- \
  sweep --encounter enc_boss_ashen_revenant --repeat 300 --level 12
```

## เส้นความยากของการสำรวจ — วัดแล้ว

เกณฑ์เดียวกับด้านบน แต่วัดทั้งด่านสำรวจ (หลายจุดต่อเนื่องกัน, HP ติดตัวข้ามจุด) แทนที่จะเป็น
การต่อสู้แยกจุดเดียว ด่าน `stg_ashfields` ด้วยโรสเตอร์เริ่มต้นของ `simrunner`
(Knight, Warden, Adept, Oracle, Stalker — ทีมเดียวกับที่ให้ 89% ในตารางก่อนหน้า)
นโยบายเลือกทางอัตโนมัติ (`AutoPick`): เลือก Rest ถ้ามีให้เลือกและทีมเหลือเลือดต่ำกว่า 50%
ไม่งั้นเลือกตัวเลือกแรกเสมอ — 300 seed ต่อระดับ:

| เลเวลทีม | อัตราจบด่าน |
| --- | --- |
| 4 | **0.0%** |
| 8 | **3.0%** |
| 12 (recommended) | **57.0%** |
| 16 | **99.7%** |
| 20 | **100.0%** |

ด่านเปิดใกล้เคียงกับ `recommendedLevel` ที่ตั้งไว้ (12) พอดี ทำซ้ำได้ด้วย:

```bash
for level in 4 8 12 16 20; do
  dotnet run --project tools/DarkMyst.SimRunner -- \
    expedition --stage stg_ashfields --repeat 300 --level "$level"
done
```

อ่านเพิ่มเรื่องกฎของด่านสำรวจได้ใน [09-expedition-spec.md](09-expedition-spec.md)

## การกันผลเพี้ยนระหว่างไคลเอนต์กับเซิร์ฟเวอร์

ผลการต่อสู้ทุกครั้งมี `Checksum` และ `RngCalls` ติดมาด้วย เมื่อระบบออนไลน์พร้อม (ระยะ D)
ให้ไคลเอนต์ส่ง checksum ของ log ที่เล่นซ้ำกลับไปด้วย:

- ตรงกัน → ปกติ
- ต่างกัน → บันทึก request ทั้งก้อนไว้ตรวจ นี่คือสัญญาณว่าสองฝั่งเริ่มคนละรุ่นแล้ว

`simrunner battle` รันทุกการต่อสู้สองครั้งแล้วเทียบ checksum อัตโนมัติ และคืนค่า 3 ถ้าไม่ตรง
จึงจับการพึ่งพาลำดับของ `Dictionary` หรือ state ที่แชร์กันโดยบังเอิญได้ทันทีที่ถูกเพิ่มเข้ามา

## บั๊กที่การเขียนเทสต์จับได้แล้ว

ภูมิคุ้มกันสตันเดิมนับเป็น "รอบ" และลดลงตอนปลายรอบ ผู้ร่ายที่เร็วกว่าเหยื่อจึงสตันซ้ำได้
ก่อนภูมิคุ้มกันจะได้กันอะไรเลย — กลไกที่ตั้งใจใส่เพื่อกันการล็อกตัวละคร กลับไม่ทำงานเลย
แก้โดยให้ภูมิคุ้มกันหมดอายุด้วยการได้ลงมือแทน

เป็นตัวอย่างว่าทำไมเกณฑ์ผ่านของระยะ A ต้องเป็น "เขียนเป็นกรณีทดสอบได้"
ไม่ใช่แค่ "เขียนเป็นเอกสารได้"
