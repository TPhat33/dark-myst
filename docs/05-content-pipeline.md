# การเพิ่มเนื้อหาและการกำหนดเวอร์ชัน

เกมนี้จะใช้เวลาส่วนใหญ่ไปกับตัวละคร ด่าน เรื่องราว และสมดุล ถ้าทุกอย่างต้องแก้โค้ด
การเพิ่มเนื้อหาจะช้ามาก ระบบจึงถูกออกแบบให้ **ตัวละครและสกิลประกอบขึ้นจากข้อมูล**

## เพิ่มอะไรได้โดยไม่แตะโค้ด

- ตัวละครใหม่ที่ใช้กลไกเดิม — เพิ่มใน `characters.json` + อ้างสกิลที่มีอยู่
- สกิลใหม่ที่ประกอบจาก `EffectKind` ที่มีอยู่ — เพิ่มใน `skills.json`
- ศัตรูและด่านใหม่ — `enemies.json`, `encounters.json`
- ปรับสมดุลทุกอย่าง — ค่าทั้งหมดเป็นข้อมูล

## ต้องเขียนโค้ดเมื่อไร

เมื่อสกิลเปลี่ยน **กติกา** จริง ๆ เช่น "โจมตีสองครั้งในตาเดียว" หรือ "สลับตำแหน่งกับเพื่อน"
กรณีแบบนี้ต้องเพิ่ม `EffectKind` หรือ `TriggerKind` ใหม่ พร้อมเทสต์ และขึ้น `CombatRules.Version`

ประเมินก่อนเสมอว่ากลไกใหม่จริงหรือแค่ค่าที่ยังไม่เปิดให้แก้ — ทางที่สองถูกกว่ามาก

## โครงสร้าง content pack

```
content/
  manifest.json       contentVersion + rulesVersion + รายชื่อไฟล์
  skills.json         สกิลทั้งหมด
  characters.json     ตัวละครทุกร่างของทุกสาย
  enemies.json        ศัตรู
  encounters.json     การจัดวางศัตรูเป็นด่าน
  progression.json    เพดานเลเวล กฎ evolve แนวทางเน้นสแตท
  stages.json         ด่านสำรวจ (ฟาร์ม): แผนที่, ตารางรางวัล, เหตุการณ์ — ดู 09-expedition-spec.md
```

`content/` คือ **แหล่งความจริงชุดเดียว** สำเนาใน `unity/.../StreamingAssets/content/`
ถูกสร้างโดย `tools/build-unity-plugins.sh` และไม่ถูก commit

## การตรวจสอบ

`ContentPack.Validate()` ทำงานทุกครั้งที่โหลด ทั้งบนเซิร์ฟเวอร์และใน CI จับ:

- สกิล ตัวละคร ศัตรู หรือด่าน ที่อ้างถึง id ที่ไม่มีอยู่
- id ซ้ำ
- ตัวละครหรือศัตรูที่ไม่มีสกิล `OnAction` ที่รับประกัน
- สายตัวละครที่ evolve ไปหาร่างที่ไม่มีอยู่ หรือขั้นที่ไม่มีสูตรรองรับ
- effect ที่ต้องมี `statusId` แต่ไม่มี (ถ้าปล่อยไว้ สถานะนั้นจะติด ซ้อน หรือถอดไม่ได้เลย)
- `rulesVersion` ในเนื้อหาไม่ตรงกับรุ่นของ engine

`MissingMemberHandling.Error` ถูกเปิดไว้โดยตั้งใจ — คีย์ที่พิมพ์ผิดจะทำให้โหลดล้มเหลว
ไม่ใช่ทำให้บอสเงียบ ๆ เสียสกิลไปหนึ่งอัน

ตรวจจากบรรทัดคำสั่ง:

```bash
dotnet run --project tools/DarkMyst.SimRunner -- validate
```

## การกำหนดเวอร์ชัน

มีสองเวอร์ชันที่แยกกัน:

| เวอร์ชัน | เปลี่ยนเมื่อ | ผูกอยู่กับ |
| --- | --- | --- |
| `CombatRules.Version` | กฎหรือค่าคงที่ของ engine เปลี่ยน | ทุก battle log |
| `contentVersion` | ข้อมูลใน `content/` เปลี่ยน | ทุกตัวละครที่ครอบครอง และทุกการสำรวจที่ค้างอยู่ |

เซิร์ฟเวอร์เก็บ content หลายเวอร์ชันพร้อมกัน เพราะ:

- **การสำรวจที่กำลังเล่นอยู่ต้องจบด้วยเวอร์ชันที่เริ่ม** ผู้เล่นจะไม่เจอสูตรหรือบอส
  เปลี่ยนกลางรอบหลังอัปเดต
- ตัวละครที่ครอบครองปักเวอร์ชันของตัวเอง การย้ายไปเวอร์ชันใหม่เป็นขั้นตอนที่ตั้งใจทำและบันทึกไว้
  (ดู [03-evolve-spec.md](03-evolve-spec.md) ข้อ 5)
- ต้องย้อนกลับ (rollback) ไปเวอร์ชันก่อนหน้าได้ถ้าอัปเดตมีปัญหา

## การกระจายเนื้อหา

Content pack ถูกอัปโหลดขึ้น CDN เป็นโฟลเดอร์ต่อเวอร์ชัน (`/content/0.2.0/…`)
ไคลเอนต์ถาม API ว่าควรใช้เวอร์ชันใด ดาวน์โหลด แคชไว้ แล้วโหลดผ่าน `ContentPack.Load()`
ตัวเดียวกับที่ใช้กับไฟล์ที่ฝังมาในแอป

Pack ที่ฝังมาในแอปเป็น fallback — ผู้เล่นที่เพิ่งติดตั้งและยังต่อเน็ตไม่ได้ ยังเปิดเกม
และเข้าสนามทดลองได้

## เครื่องมือที่ต้องทำในระยะ D

- หน้าจัดการ (Vue + TS) สำหรับเพิ่มตัวละคร สกิล ด่าน และดู diff ระหว่างเวอร์ชัน
- ปุ่มรัน `sweep` จากหน้าจัดการ เพื่อดูผลสมดุลก่อนเผยแพร่
- workflow เผยแพร่: แก้ → validate → sweep → ตรวจทาน → เผยแพร่ → (ย้อนกลับได้)
