## การจัดทีมมีผลจริงไหม — วัดแล้ว

เกณฑ์ผ่านของระยะ B คือ *"เปลี่ยนทีมแล้วผลต่างอย่างเข้าใจได้"* ซึ่งวัดได้ ไม่ใช่แค่รู้สึกเอา
รันกับบอสที่เลเวลโรสเตอร์ 12 ครั้งละ 300 seed:

| ทีม | อัตราชนะ |
| --- | --- |
| Knight, Warden, Adept, Oracle, Stalker (แทงก์หน้า หมอหลัง) | **89%** |
| Adept, Stalker, Knight, Warden, Oracle (เอาตัวบางขึ้นหน้า) | **80%** |
| Knight, Warden, Maiden, Hexer, Stalker (ไม่มีหมอ) | **0%** |

อ่านได้ว่า: ตำแหน่งมีผลจริงแต่ไม่ถึงกับชี้ขาด ส่วนการไม่มีตัวฮีลเลยคือแพ้ขาด
นี่คือรูปร่างที่ต้องการ — ตัดสินใจผิดแล้วเจ็บ แต่ยังกู้คืนได้ด้วยการปรับทีม

## เส้นความยาก — วัดแล้วเช่นกัน

อัตราชนะตามเลเวลของทีม (300 seed ต่อช่อง):

| ด่าน | lv1 | lv4–5 | lv8–10 | lv16+ |
| --- | --- | --- | --- | --- |
| `enc_tutorial_hounds` | 100% | 100% | 100% | 100% |
| `enc_crypt_patrol` | 0% | 40% | 100% | 100% |
| `enc_boss_ashen_revenant` | 0% | — | 56% (lv10) | 100% |

ด่านสอนต้องชนะเสมอ ด่านฟาร์มเปิดประมาณเลเวล 4–8 บอสเปิดประมาณเลเวล 10–16
นี่คือเหตุผลที่ผู้เล่นต้องกลับไปฟาร์ม

ทำซ้ำได้ด้วย:

```bash
dotnet run --project tools/DarkMyst.SimRunner -- \
  sweep --encounter enc_boss_ashen_revenant --repeat 300 --level 12
```

## เส้นความยากของการสำรวจ — วัดแล้ว

เกณฑ์เดียวกับด้านบน แต่วัดทั้งด่านสำรวจ (หลายจุดต่อเนื่องกัน, HP ติดตัวข้ามจุด) แทนที่จะเป็น
การต่อสู้แยกจุดเดียว ด่าน `stg_ashfields` ด้วยโรสเตอร์เริ่มต้นของ `simrunner`
(Knight, Warden, Adept, Oracle, Stalker — ทีมเดียวกับที่ให้ 89% ในตารางก่อนหน้า)
นโยบายเลือกทางอัตโนมัติ (`AutoPick`): เลือก Rest ถ้ามีให้เลือกและทีมเหลือเลือดต่ำกว่า 50%
ไม่งั้นเลือกตัวเลือกแรกเสมอ — 300 seed ต่อระดับ:

| เลเวลทีม | อัตราจบด่าน |
| --- | --- |
| 4 | **0.0%** |
| 8 | **3.0%** |
| 12 (recommended) | **57.0%** |
| 16 | **99.7%** |
| 20 | **100.0%** |

ด่านเปิดใกล้เคียงกับ `recommendedLevel` ที่ตั้งไว้ (12) พอดี ทำซ้ำได้ด้วย:

```bash
for level in 4 8 12 16 20; do
  dotnet run --project tools/DarkMyst.SimRunner -- \
    expedition --stage stg_ashfields --repeat 300 --level "$level"
done
```

อ่านเพิ่มเรื่องกฎของด่านสำรวจได้ใน [09-expedition-spec.md](09-expedition-spec.md)

## การกันผลเพี้ยนระหว่างไคลเอนต์กับเซิร์ฟเวอร์

ผลการต่อสู้ทุกครั้งมี `Checksum` และ `RngCalls` ติดมาด้วย เมื่อระบบออนไลน์พร้อม (ระยะ D)
ให้ไคลเอนต์ส่ง checksum ของ log ที่เล่นซ้ำกลับไปด้วย:

- ตรงกัน → ปกติ
- ต่างกัน → บันทึก request ทั้งก้อนไว้ตรวจ นี่คือสัญญาณว่าสองฝั่งเริ่มคนละรุ่นแล้ว

`simrunner battle` รันทุกการต่อสู้สองครั้งแล้วเทียบ checksum อัตโนมัติ และคืนค่า 3 ถ้าไม่ตรง
จึงจับการพึ่งพาลำดับของ `Dictionary` หรือ state ที่แชร์กันโดยบังเอิญได้ทันทีที่ถูกเพิ่มเข้ามา

## บั๊กที่การเขียนเทสต์จับได้แล้ว

ภูมิคุ้มกันสตันเดิมนับเป็น "รอบ" และลดลงตอนปลายรอบ ผู้ร่ายที่เร็วกว่าเหยื่อจึงสตันซ้ำได้
ก่อนภูมิคุ้มกันจะได้กันอะไรเลย — กลไกที่ตั้งใจใส่เพื่อกันการล็อกตัวละคร กลับไม่ทำงานเลย
แก้โดยให้ภูมิคุ้มกันหมดอายุด้วยการได้ลงมือแทน

เป็นตัวอย่างว่าทำไมเกณฑ์ผ่านของระยะ A ต้องเป็น "เขียนเป็นกรณีทดสอบได้"
ไม่ใช่แค่ "เขียนเป็นเอกสารได้"
